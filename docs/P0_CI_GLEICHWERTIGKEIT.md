## Vorschlag für ein getrenntes P0-Folgepaket

| Phase | Kleine Änderung zur Prüfung | Gegenprobe und Rücknahme |
| --- | --- | --- |
| Schnellprüfung | Vor umfangreichen Läufen die vorhandene P0-Inventur und die etwa sechs Sekunden lange Regel208-Genesis-/Altbuild-Prüfung sichtbar machen. Auf reinem Doku-Diff reicht als branchgebundener Workflow die ausgelöste Inventur, die vollständige Produktregression wird weiterhin vor der Produktintegration belegt. | Im isolierten Probelauf eine fehlende Abhängigkeit, einen kaputten Doc-Link und ein unzulässiges Save-Format einspeisen. Die passende Schnellprüfung muss rot sein. Ein fehlender schneller Beleg bleibt offen. Bei unerwarteter Blockade zusätzliche Schnell-Orchestrierung zurücknehmen und Originaljobs einzeln ausführen. |

Relay-Abdeckung über zwei Linux-Images, Browser-Versionen oder lange Simulationen bleiben bis zu einem eigenen messbaren Vergleich außerhalb dieser Konsolidierung. ## Tarifunabhängiger Ablauf für PC und iPad

**iPad · GitHub im Browser**

1. [Auftragsboard](https://github.com/tobiasfranziskus/Check/issues/658) und den zugehörigen Draft öffnen. Dateigrenze, Main-/Base-/Head-SHA und Abnahmekriterien notieren. Unter **Files changed** und **Checks** die geänderten Pfade, relevanten Originaljobs und Versuch prüfen. Bei einem Merge-Ref im Joblog die tatsächlich ausgecheckte Version prüfen.
2. Falls Schreibrecht vorhanden, **Actions → P0 - CI-Nachweis → Run workflow** auf **main** mit PR-Nummer und exakter Dateigrenze starten. Summary und `p0-ci-nachweis` öffnen. Das integrierte Werkzeug dieses Basis-SHA deckt laut Runbook P0-Inventur und JS ab. Restliche Workflow-/Job-/Originalbelege von Hand ergänzen. GitHub verlangt für den manuellen Start eine auf dem Standardbranch registrierte Definition und die passenden Berechtigungen. Ausgelaufene Artefakte über noch verfügbare Originalbelege oder einen neuen, identifizierten Lauf ersetzen.
3. Kleine Textkorrekturen im GitHub-Dateieditor auf eigenem Branch committen und als Draft öffnen. Ohne Schreibrecht Quellen und öffentliche Checks lesen, nötigenfalls einen eigenen Fork oder die Übergabe an 00 nutzen. Browserzugriff schafft kein lokales Node22-Terminal. Am iPad aufgezeichnete echte Safari-Beobachtung separat mit Gerät, Orientierung, SHA bzw. URL sowie Schritt und Ergebnis melden.

**Windows/Linux-PC · Git, Node22 und optional lokales Modell**

```sh
git status --short
git fetch origin main
git switch --no-track -c research/eigener-auftrag origin/main
git rev-parse HEAD
node --version
node --test "tests/*.test.mjs"
node scripts/p0-prototype-deps.mjs --check
git diff --check
git diff --name-status origin/main...HEAD
```

Bei einem Fork den Originalbranch über `upstream/main` holen. Für betroffene Browserpfade den genauen Playwright-Pin und die Engines aus der Matrix einsetzen. Das [Runbook](P0_FREE_WEITERBETRIEB.md) enthält Linux-/PowerShell-Aufrufe für J4e. Auf Windows oder Linux mit abweichender Browserumgebung die tatsächliche OS-/Browser-Version berichten. Die Chromium-/WebKit-Desktopemulation deckt Gerätepfade funktional ab. Offene iPad-Hardware-/NAS-Schritte bleiben separat. Optional am geprüften Tool-Commit mit `gh auth status` einen möglichst lesenden Zugang prüfen und `node tools/p0-free-handoff.cjs --pr <Nummer> --allow '<nur erlaubte Pfade>' --out <temporärer Ordner>` ausführen. Bei fehlender `gh`-Anmeldung Originalprotokolle im Browser öffnen. Vor Verwendung eines Schreibzugangs den Auftrag, die Repo-Rolle und den Branch prüfen.

Ein kleines lokales Modell kann in einem Paket den exakten Auftrag, die relevanten Dateien und wenige Originalfehlerzeilen erhalten. Der PC führt die Prüfbefehle aus, das Modell formuliert einen kleinen Patch und der Mensch kontrolliert Diff, Exitcode und Originalwerte. Eigenen Draft erstellen und auf #658 rückmelden. Ohne Modell funktioniert derselbe Ablauf mit Editor und Git. Zugangsdaten und private Spielstände bleiben lokal. Ein wichtiger Befund wird als kurze Übergabe gesichert:

```text
Auftrag und erlaubte Pfade | Base/Head | Testmerge (oder Main nach Merge)
Befehl und tatsächlicher Ausgang | Run/Job/Versuch | Artefakt, falls verfügbar
Abbruch/Skip/offenes Gate | nächster konkreter Schritt an 00
```

**Zugriff im Audit:** Der lokale Git-Clone und Git-Readback sowie ein direkter GET des öffentlichen Root (HTTP 200) waren möglich. Das installierte `gh` meldete keine aktive Anmeldung. Die auftragsbezogenen Originaljobprotokolle, Job-/Artefaktlisten und Schreiboperationen sind über den GitHub-Zugang der Sitzung verfügbar. Der lokale Root-GET bestätigt die Erreichbarkeit, der SHA- und Spielpfadbeleg stammt aus #682. Physische Hardware und private NAS-Instanz wurden in diesem Audit nicht geprüft.
